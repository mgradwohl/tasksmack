# Implemented Features

This is the canonical inventory of user-visible and engineering features currently implemented in TaskSmack. Partial capabilities are called out explicitly; planned work belongs in [tasksmack.md](https://github.com/mgradwohl/tasksmack/blob/main/tasksmack.md).

## Process Monitoring and Control

| Feature | Current behavior |
|---------|------------------|
| Process table | Sortable, filterable list with PID, PPID, name and icon, command, user, publisher and type (Windows), container (Linux), services, state/status, CPU, memory (resident, virtual, shared, peak, and on Linux private and swap), CPU time, start time, priority, thread/handle/GDI counts, affinity, page faults, I/O, network, power (Linux with RAPL), GPU and NPU columns where supported; optional inline bars or sparklines behind the numeric columns; rows of processes that started in the last five seconds tinted, fading out, and processes that just exited kept for two seconds as dimmed, uncounted, unselectable rows where they were (#3060) |
| Process tree | Collapsible parent/child hierarchy with cached rebuilds |
| Process details | Overview with Identity, Runtime and Actions cards, recent crashes, and on-demand sections for services, environment variables, connections, modules, security context and open files; capability-driven chart tabs for CPU, memory, I/O, network, GPU and NPU data |
| Column configuration | The header context menu and the toolbar's **Columns** menu (with **Reset columns**) control visibility; settings persist in `config.toml` |
| Stable process identity | PID and process start time prevent counter reuse when an operating system recycles a PID |
| Process actions | Terminate, force terminate, suspend/resume, priority and CPU affinity changes on Linux and Windows; I/O priority (ionice class and level) and any of SIGHUP, SIGINT, SIGQUIT, SIGUSR1 and SIGUSR2 from the row menu (#3063) on Linux; Efficiency mode on and off (EcoQoS and the Idle class, the class it had restored after) in the row menu and Process Details' Actions card on Windows (#3071); Efficiency mode on Linux (#3202): nice 19 for every thread plus `cpu.weight` 1 on the process's cgroup when it is alone there and the file is writable, the previous nice and weight remembered per PID and start time for off (`LinuxEfficiencyMode.h`), and **Efficiency Mode** as the Status of a process at nice 19; Analyze wait chain in the row menu and Process Details' Actions card on Windows (#3084): each thread's chain from `GetThreadWaitChain` (one synchronous WCT session; at most 1,024 threads, 16 nodes each and 5 s) on a worker, shown as a tree with deadlocks first, End process (the Kill confirmation) on a blocking process; and a **Not responding** Status from one `IsHungAppWindow` walk of the visible top-level windows a sample |
| Process dump files | "Create dump file..." in the Processes row menu and Process Details' Actions card (#807). On Linux, a core file written by gdb's `gcore` (offered only when `gcore` is installed), with the same confirm, folder choice (SDL's folder dialog), free-space warning, progress and Cancel. On Windows, a full-memory minidump (`MiniDumpWriteDump`, dbghelp.dll loaded from System32 on first use) on a worker thread, with progress, Cancel, Open folder, and clear messages for access denied, protected processes, 32-on-64 dumps and a full disk. Since #2001 it is written from a `PssCaptureSnapshot` clone, so the process pauses only for the snapshot (live, saying why, when the snapshot fails), to `%TEMP%` or a folder chosen with the confirm's "Save dump to..." (`IFileOpenDialog`, remembered as `[dumps] folder`), and the confirm warns early when the folder's drive may be too full |
| Open file location and Search online | In the Processes row menu (#3064). Open file location reads `/proc/<pid>/exe` through the identity check and asks the session's file manager to show it selected (`org.freedesktop.FileManager1.ShowItems` over sd-bus), falling back to `xdg-open` on its folder; as root for another user, the folder opens as that user. Search online opens a DuckDuckGo search for the process name only, never its path. Both run on the row action worker. Windows: Open file location is the Windows lane's part (`SHOpenFolderAndSelectItems`) |
| Pinned processes | Pin to top / Unpin in the Processes row menu (#3061): every process of that name stays first through any sort and filter (`ProcessPins::pinnedFirst`, a stable partition after the sort), marked with a thumbtack; in tree view pinned processes come first among their siblings. Saved by name as `[process_table] pinned` (written only when there are any; at most 64 names of up to 256 bytes) |
| Run new task | The Processes toolbar's rocket button (#3065): a command line, the last 10 run (`[run_task] recent`), Browse... (`Core::showOpenFileDialog`) and, where the platform can, Run as administrator. `IProcessActions::runProgram`; Linux splits the words without a shell (`Platform::CommandWords`), finds the program on PATH, and starts it detached, through `pkexec` as administrator, and as the session user when TaskSmack runs as root for them. Windows (CreateProcess / ShellExecuteEx runas) is the Windows lane's part |
| Close connection (UI) | The Connections tab's row menu (#3066, Linux): right-click, **Close connection...**, a confirm naming the process and both endpoints, then `closeConnection()` on a worker (`ConnectionCloseControl` over `ProcessActionRun`) with the result above the table and **Authenticate and retry** on a permission refusal (`AuthorizedAction::Kind::CloseConnection`). Only a held TCP connection with a peer (`closeConnectionRefusal()`); `SystemConnection::socketInode` names the socket. The actions come from `makeConnectionsPanelActions()` (brokered) |
| Close connection (platform) | `IProcessActions::closeConnection(target, socketInode)` (#3066, Linux): after the pidfd-first identity check, the descriptor holding `socket:[inode]` is copied with `pidfd_getfd()` (Linux 5.6+) and `shutdown(SHUT_RDWR)`, so the peer sees the connection end; the process's own descriptor stays open. Another user's process: the helper's `CloseConnection` request (protocol v10) with its existing `CAP_SYS_PTRACE`, retried by `BrokeredProcessActions`; `pidfd_getfd` and `shutdown` are in the helper's seccomp allow-list (maintainer's call). The Connections tab's row menu offers it (below) |
| systemd units in Startup | The Linux Startup tab also lists enabled systemd user units (#3082): the `.service` / `.timer` links in `~/.config/systemd/user` and `/etc/systemd/user`'s `default.target.wants`, `graphical-session.target.wants` and `timers.target.wants` (`StartupLocation::SystemdUserUnit` / `SystemdSystemUnit`), parsed by `SystemdUnitFile::parse()` (Description, the first ExecStart, a timer's schedule and Unit=). Read-only (`notSwitchableReason`); switching through `systemctl --user` and cron follow |
| Per-connection rates | The Connections tab's Sent/s and Received/s columns (#3079, Linux TCP): `dumpInetSockets()` asks TCP dumps for INET_DIAG_INFO and reads tcp_info's `bytes_acked` / `bytes_received` into each socket; `ConnectionsModel` keeps each reading's counters by `Connections::socketKey()` and publishes `connectionRates()` (unknown on a socket's first reading, for UDP, or when a counter went backwards). A per-remote-host rollup and Process Details' Connections section follow |
| Signature column | A Signature column (hidden by default) and a Process Details Identity row on Windows (#3070): each process image's Authenticode signature from `WinVerifyTrust` (WINTRUST_ACTION_GENERIC_VERIFY_V2, `WTD_REVOKE_NONE` and `WTD_CACHE_ONLY_URL_RETRIEVAL`, so never the network), embedded or through the system catalogs (`CryptCATAdminAcquireContext2` / `CryptCATAdminCalcHashFromFileHandle2` / `CryptCATAdminEnumCatalogFromHash`, SHA-256 then SHA-1), the check the Drivers section's images already used (#1661), now shared in `WindowsSignatureCheck.cpp` behind a `TrustApiFunctions` seam. Checked on the process probe's own `ts-sig-check` worker at background priority, one file at a time with a pause between (`SIGNATURE_CHECK_PAUSE_MS`), never in a sample: a process is published at once and its signature taken on a later sample (`WindowsSignatureWorker.h`). Answers cached by path, size and last write time (`SignatureCache`, at most `SIGNATURE_CACHE_MAX_FILES`), so another process of the same image costs a file stamp read. Shown as a check mark and the signer, Unsigned, Invalid or Not checked (`Platform::signatureLabel()`), with the detail on hover; sorted verified-by-signer first. Linux: capability false, the dash |
| Scheduling policy | A Scheduling Policy column (hidden by default) and a Process Details Runtime row on Linux (#3086): `/proc/[pid]/stat` fields 40-41 (rt_priority, policy), read optionally past rss by `ProcParsing::parseStatFields()`, mapped by `Platform::schedPolicyFromLinux()` and worded by `schedPolicyLabel()` ("Normal", "FIFO 50") once per sample in `ProcessModel`; sorted by policy then RT priority. Setting a policy (FIFO/RR through the helper's CAP_SYS_NICE) follows |
| Priority keys (F7/F8) | F7 / F8 on the Processes tab step the one selected process's priority higher / lower at once (#3097): `NiceStep::next()` (nice +-1, or the next Windows class between Idle and High), run with `runRowAction()` and `setPriority()`, with `AuthorizedAction::SetPriority` for Authenticate and retry; "already at the highest/lowest" at the ends. In the function-key map and the Help window |
| Incremental search (/) | `/` over the Processes table opens a Find box beside the filter (#3097): typing jumps the selection to the first visible row from the selected one whose name contains the text (ASCII case ignored, `IncrementalSearch::findMatch`), Enter to the next (wrapping), Esc closes; applied with the keyboard's moves in `applyKeyboardInput()`, so it selects and scrolls as they do. Listed in the Help window |
| Find handles | The Processes toolbar's magnifier button and Ctrl+Shift+F (#3067); Ctrl+F puts the cursor in the filter box: a substring search of every process's open files and loaded modules on the `ts-find-handles` worker (`Domain::HandleSearch`, `FindHandlesDialog`), through the readers Process Details uses (`IProcessOpenFilesReader`, `IProcessModulesReader`), published in batches; sortable results, at most 10,000; processes another user owns counted and searched again through `readAuthorized()` behind one prompt. Linux reads `/proc/<pid>/fd` and `/proc/<pid>/maps`; Windows (one pass over the system handle table) is the Windows lane's part, and until then Windows has no Find handles button (`makeProcessesPanelPlatform()` gives it no readers) |
| Sort menu (F6) | F6 on the Processes tab opens **Sort by** (#3097): the table's visible, sortable columns (read in the table before the popup, which has no current table), the sort column ticked; a pick calls `TableSetColumnSortDirection()` (the column's preferred direction, or the reverse when it is the sort column already). In the function-key map and the Help window's list |
| Stuck-process tint | A process in D (Disk Sleep) for `StuckProcesses::STUCK_SECONDS` (2 s) or more has its Processes row tinted in `statusDiskSleep` (#3097), ahead of the new-process tint; decided once per generation (`StuckProcesses::Tracker`), so drawing needs no clock |
| Compressed swap meter | The Memory chart's value strip shows **Compressed** (#3087, Linux): zram (every `/sys/block/zramN/mm_stat`, summed; the device list relisted every `ZRAM_RESCAN_INTERVAL_SECONDS`) and zswap (`Zswap`/`Zswapped` in `/proc/meminfo`) as a ratio and sizes, with a per-kind breakdown and the ratio's range over the window in its tooltip (`MemoryCounters`, `SystemSnapshot::compressionRatio`, `SystemModel`'s `compressionRatioHistory`). The ratio history is drawn on the Memory chart as **Compression →**, on a right-hand axis (`setupSecondaryRateAxis()`), only while the window holds a reading |
| Group by | The Processes toolbar's Group control (#3068): None, Unit, Container, App or User (per-user totals, #3076's read-only first part) (an app's name from its systemd scope or service: desktop apps, Flatpaks, Snaps). Collapsible group header rows with the process count and Σ totals in the summable columns (`ProcessGrouping::buildGroups`, exited rows listed but not counted), groups ordered by their totals in the sort column, Ungrouped last; a mode of the List view; saved as `[process_table] group_by` |
| Process threads | Process Details' Threads section (#3069, Linux): TID, name, state, CPU % (share of the machine, from two reads), CPU time, nice and start time (the read's boot time plus the thread's start ticks) per thread, sortable and filterable, read from `/proc/[pid]/task/*/stat` through the identity check on a worker, only while the section is open, at the Settings interval (`IProcessThreadsReader`, `ProcessThreadsView`). Windows (Toolhelp) is the Windows lane's part; per-thread suspend/resume/end too; another user's process (hidepid) through the helper's `ReadThreads` (protocol v11) with **Authenticate to read** |
| Users tab | A row per signed-in user (#3076, Linux): `IUserSessions` (logind `ListSessions` and each session's properties, `LockSession` and `TerminateSession` through the service actions' polkit-aware call), `UsersModel` sampled on the tab's own `BackgroundSampler` at the Settings interval only while the tab is shown, per-user Σ CPU, memory, disk and network from the Processes model's published snapshots (`ProcessGrouping::Totals`), sessions and processes under each user; **Lock** at once and **Sign out...** behind a confirm (`SessionActionControl`), with Authenticate and retry. Windows (WTS sessions, Disconnect) follows |
| Connections tab | Every TCP and UDP socket with its holder (#3066, Linux): `ISystemConnectionsReader` (netlink INET_DIAG dumps with a /proc/net fallback, holders from `buildInodeToPidMap()`), `ConnectionsModel` sampled on the tab's own `BackgroundSampler` at the Settings interval only while the tab is shown (`SamplingGate`), and a sortable, filterable table; a row click selects its process. New sockets tinted and fading out over 5 s, closed ones kept 2 s dimmed (`ConnectionChangeTracker`, keyed on `selectionKey()`; the first generation lights nothing). Windows follows |
| Privileged helper (Linux) | With the `.deb` (or an `.rpm` built from source), an action or read another user's process refuses (end, suspend, resume, priority, I/O priority, affinity; Process Details' environment, modules, open files, connections and PSS/USS) and System Information's root-only facts (firmware serials, UUID and SMBIOS version, memory modules, every user's crashes) offer **Authenticate and retry** / **Authenticate to read**: polkit asks for an administrator's password and `tasksmack-helper` does that request as root, from `/usr/libexec/tasksmack/` |
| Privileged helper (Windows) | When TaskSmack isn't running as administrator, an action Windows refuses for want of rights (Terminate, Kill, Suspend, Resume, priority, affinity) offers **Retry as administrator**, and Process Details' Modules, Open files and Connections offer **Read as administrator**: `TaskSmackHelper.exe` is started elevated through UAC and does that request. Offered only in Authenticode-signed releases (#2302) installed where only an administrator can change them, such as `C:\Program Files\TaskSmack`; see the FAQ's [Acting as an administrator on Windows](../guide/faq.md#acting-as-an-administrator-on-windows) |
| System call tracing | Linux only: the Actions block on Process Details' Overview opens a terminal running `strace -f -tt -p <PID>` (htop-style), started detached with no shell; disabled with the reason when strace or a terminal is missing, and refused with an explanation when ptrace (another user's process, Yama `ptrace_scope`) would not allow the attach |
| Multi-select and batch actions | Ctrl/Shift+click and Ctrl+A select several processes by identity; Suspend, Resume, Terminate and Kill act on all of them behind one confirmation, run on a worker with a progress count, and end in one summary result; one priority (nice value, or class on Windows) can be set on all of them the same way; **End process tree** ends a process and all its descendants, children first, the same way (#3059) |
| Disk I/O rates | Per-process read/write rates; Linux access to other users' processes needs `CAP_DAC_READ_SEARCH` + `CAP_SYS_PTRACE` in the effective set (root with its normal capabilities has them; root alone isn't enough where capabilities are dropped) |
| Network rates | Per-process sent/received rates over each sampling interval, TCP only by default; Linux uses Netlink, Windows uses TCP EStats when running as administrator, plus opt-in UDP from an ETW kernel network session |
| GPU attribution | Per-process utilization, memory, device, and engine data when supported by the active GPU backend |

## System Monitoring

| Feature | Current behavior |
|---------|------------------|
| CPU | Total and per-core utilization, breakdowns, and bounded history |
| Memory and swap | Current usage, availability, cache data, swap, and bounded history |
| Storage | System and per-device throughput and history |
| Network | System-wide and per-interface throughput, totals, status, and link speed in the System Overview |
| GPU | Per-device utilization, memory, temperature, power, clocks, fan, encoder/decoder data when exposed by the backend |
| Battery and power | Charge, power flow, time remaining/time to full, and health when a battery is present |
| NPU | Utilization and memory of NPUs and other compute accelerators (Windows DXCore; Linux accel subsystem), kept apart from the GPU figures |
| Linux-only metrics | Load averages, pressure stall information (CPU, memory and I/O, #3062), I/O wait and steal time |

## User Experience and Configuration

| Feature | Current behavior |
|---------|------------------|
| Tabbed shell | Six tabs: the machine's metrics, Processes, Process Details, Services, Startup, and System (System Information) |
| Services | Windows Service Control Manager and Linux systemd services: list, start, stop, restart and set the startup type, with confirmations for critical services |
| Startup apps | Windows only: Run/RunOnce keys, Startup folders and packaged apps' startup tasks, enabled and disabled as Task Manager does |
| Startup impact | The Startup tab's **Startup impact** column (#3073, Windows): High / Medium / Low / None (disabled) / Not measured, with Task Manager's documented thresholds (KB5022092: over 1 s CPU or 3 MB disk is High, under 300 ms and 300 KB is Low; `Domain/StartupImpact.h`), and the CPU time, disk I/O, process count and sign-in time in its tooltip; sortable, highest first. Read non-elevated from the user's WDI files `%SystemRoot%\System32\wdi\LogFiles\StartupInfo\<SID>_StartupInfo1-5.xml`, the newest sign-in (`WindowsStartupImpact.h`); each entry's program matched by path (case-insensitive, `\\?\` and quotes dropped) and its process tree summed (`Platform/StartupImpact.h`). Read on the Startup sampler with the first sample and then every `STARTUP_IMPACT_REFRESH_SECONDS` (600 s); hidden on Linux |
| System Information | Operating system, firmware and board, memory modules, commit and paging, storage, security, sensors, graphics and displays, network adapters, boot performance, devices, drivers or kernel modules, and recent crashes; identifiers hidden until asked for; Copy and Save report (text or JSON) |
| Themes | 20 bundled TOML themes plus user themes |
| Persistent settings | Theme, font size, process columns, sampling, history, window state, and advanced metric/UI settings |
| Update check | Opt-in, notify only (#3093 part 1; Linux #3238): Settings' **Check for updates daily** (off by default; nothing is sent while it is off) and **Check now**. At most once a day (`UPDATE_CHECK_INTERVAL_HOURS`, measured from `[updates] last_check`, a failed check counting) the `ts-update-check` worker sends one HTTPS GET of GitHub's `/repos/mgradwohl/tasksmack/releases/latest` through WinHTTP (`Platform::WindowsHttpsClient`, User-Agent `TaskSmack/<version>`, no cookies or credentials, 10 s); `Domain::UpdateCheck` reads the reply's top-level `tag_name` and `html_url` (a bounded, non-recursive JSON reader, fuzzed by `fuzz_release_json`), compares SemVer, and the status bar shows "TaskSmack vX.Y.Z is available", linking to the release page, with an X that dismisses that version. Nothing is downloaded. On Linux the request goes through `LinuxHttpsClient` over libcurl (a build dependency found with pkg-config; https-only, redirects too, verification on, only the request's headers, the whole request bounded by its timeout, the body capped, a stop aborting the transfer) |
| Start at sign-in | Opt-in, per user (#3093 part 2; Linux #3254): Settings' **Start TaskSmack when I sign in** (off by default) writes, on Save, the HKCU Run key's `TaskSmack` value as the running exe's quoted path and `--minimized` (`Domain::StartAtLogin::runCommand()`), and deletes it when turned off; no other value is touched and nothing goes in `config.toml`. Read and written on the `ts-sign-in` worker (`App::StartAtLoginSetting`) through `Platform::IStartAtLogin` (`WindowsStartAtLogin`, a function table over advapi32). Settings shows Off, On, or another copy's path with **Repair**, and warns a copy outside Program Files to turn it off before it moves. `--minimized` creates the window hidden and shows it with `SW_SHOWMINNOACTIVE`, so it never takes the focus and draws nothing until restored. The NSIS uninstaller deletes the value when it starts that installation's TaskSmack.exe. Linux's XDG autostart entry is agent:WSL's part; until then the row is hidden there; on Linux the per-user XDG autostart entry `~/.config/autostart/tasksmack.desktop` (`LinuxStartAtLogin`: the Exec quoted and escaped as the Desktop Entry spec asks, read back the same; Hidden or GNOME-disabled reads as off) |
| Sampling controls | Refresh interval from 100 ms to 5 seconds; default 1 second |
| History controls | Retention from 10 seconds to 30 minutes; default 5 minutes |
| Keyboard shortcuts | htop-style F1 Help (shortcuts, column reference, tabs), F2 Settings, F5 tree view, F9 Kill (confirmed; every selected process with several selected), F10 Quit; Processes table navigation with arrows, j/k, Page Up/Down, Home/End, g/G, Left/Right to collapse/expand in tree view, Ctrl+A to select every row, and hold Ctrl to freeze the table |
| Capability-aware UI | Unsupported metrics and actions are hidden; reduced privileges can trigger an elevation notice |
| Responsive sampling | Separate process and system `BackgroundSampler` workers isolate workloads; immutable versioned System/Storage/GPU publications, process snapshot versions, and background tree building avoid render-frame locks, redundant copies, stale history entries, and UI stalls |
| Resize pipeline | Batched SDL3 event handling, event-driven viewport updates, idle throttling, and minimized throttling |

## Platform Backends

| Capability | Linux | Windows |
|------------|-------|---------|
| Process/system metrics | `/proc`, sysfs, Netlink, POSIX APIs | Native system and process APIs |
| Process I/O | `/proc/[pid]/io`, permission-dependent | `SystemProcessInformation` snapshot |
| Per-process network | Netlink `INET_DIAG`, Linux 4.2+ | TCP EStats, administrator privileges required |
| NVIDIA GPU | NVML | NVML |
| AMD GPU | ROCm SMI | DXGI/PDH capability-dependent data |
| Intel/generic GPU | DRM/sysfs | DXGI/PDH |
| Stop/resume | `SIGSTOP` / `SIGCONT` | `NtSuspendProcess` / `NtResumeProcess` on a start-time-checked handle; critical and protected processes, PID 4 and TaskSmack itself are never suspended (#2582) |
| Process environment variables | `/proc/[pid]/environ`, on demand for the selected process; secret-looking values masked until revealed | The environment block out of the process's PEB (`NtQueryInformationProcess(ProcessBasicInformation)`, `ReadProcessMemory`) on a start-time-checked handle, on demand for the selected process, capped at 1 MiB and 4096 variables; the same masking; 32-bit (WOW64) processes not yet (#2569) |
| Process security context | `/proc/[pid]/status` IDs, capabilities, `no_new_privs`, seccomp, LSM label and cgroup | The process token: user, integrity level, elevation, privileges and groups |
| Process dump files | gdb's `gcore` | `MiniDumpWriteDump` from a `PssCaptureSnapshot` clone |
| Per-process connections (netstat-style) | `/proc/[pid]/fd` socket inodes matched against `INET_DIAG` (fallback `/proc/[pid]/net/{tcp,tcp6,udp,udp6}`), on demand for the selected process | `GetExtendedTcpTable` / `GetExtendedUdpTable` owner-PID rows (IPv4 and IPv6) after a start-time check, on demand for the selected process (#1489) |
| Minimum supported OS | Supported Linux distributions with required runtime libraries | Windows 10 version 1903 |

| CI and security | Linux/Windows builds, coverage thresholds, CodeQL, OSV, dependency review, Scorecard, sanitizer and static-analysis workflows |
| Releases | Strict SemVer tags drive packaging and a git-cliff changelog pull request |
